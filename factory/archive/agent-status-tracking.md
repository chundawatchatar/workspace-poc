## Agent status tracking

For Claude Code and Codex, each tab shows whether the agent is working, waiting for the user, or idle; the sidebar counts agents per state for each workspace; and the user is notified when an agent finishes, asks a question or needs permission (AG-1 to AG-5 in `docs/REQUIREMENTS.md`). This is local: the work lives in `packages/terminal`, `apps/ptyd-bun`, `apps/host`, `packages/shared` and `packages/terminal-ui`, so `apps/web` and `apps/client` get it through `<TerminalUI>` without app-specific code, and the server relays it unchanged.

Builds on what exists: agent detection from the process (`packages/terminal/src/agents.ts`, `SessionInfo.agent`, six agent kinds), the OSC 9;4 progress report (`SessionInfo.progress`, shown as a spinner or error icon on tabs and in the sidebar), attention from the bell and notifications (NOTE-1 to NOTE-3), and agent resume after the daemon restarts. Decisions: tracking never edits the user's own agent settings files (AG-4); agent events carry only a state and a short fixed reason, never prompts, tool input or output (SEC-3); the channel that agents report on is reachable only from the same machine and only by the session that owns it (SEC-1), and is never exposed through the tunnel or relay. Run these one at a time with `/factory next`, not in parallel: each line builds on the ones above it, and the first one decides the design the others follow.
