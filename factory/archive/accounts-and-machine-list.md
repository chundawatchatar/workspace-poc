## Accounts and machine list

Users sign in to the global app (`apps/client`) and see the machines linked to their account, with whether each is online (REM-1, REM-4). Accounts live only in the cloud server (`apps/server`) and Postgres. They never replace the machine's access key: the host still checks its key on every request. The accounts API never receives or stores a machine's access key; the relay still sees keys in transit (header and first socket message) until end-to-end encryption (REM-2) lands, so nothing here may log, persist or act on them. The rules in `docs/architecture.md` (the server routes on the envelope, only the host checks access, the client build stays static) still hold.

Decisions: Drizzle ORM with drizzle-kit migrations (no Prisma), Bun's built-in SQL driver, and PGlite in tests so `bun test` never needs Docker; Mailpit catches every email in development; the client becomes a TanStack Start app in SPA mode (static output, still served by the server) using TanStack Query, TanStack Form and TanStack Table. Authentication uses Better Auth (exact version pinned) with its Drizzle adapter: email and password, email verification, password reset and database sessions in an httpOnly cookie, with the cookie cache turned off so revoking a session takes effect on the next request. Better Auth owns `/api/auth/*` and its own tables (`user`, `session`, `account`, `verification`), typed by its own client; every other endpoint is a Zod contract in `packages/shared/src/contracts/` served under `/api`, and every other table goes through the authorized data layer. OAuth and billing are out of this phase. Each job updates `AGENTS.md` and `docs/architecture.md` where it changes a rule.
